## Abstract

Defines the HTTP observability server: base URL, endpoints, `LiveState` structure, SSE event stream, and the `track_live_state` background task that folds scheduler events into the live snapshot.

## Specification

### Server binding

The server MUST bind to `http://127.0.0.1:{port}` where `port` is configurable via the CLI (`--port`). The default port is `7773`. When `--port 0` is passed, the server MUST be disabled.

CORS MUST be enabled for all origins.

### Endpoints

**`GET /api/graph`** — MUST return the `GraphSpec` as a JSON body. The spec is static for the lifetime of the server process.

**`GET /api/state`** — MUST return a `LiveState` JSON snapshot. `elapsed_secs` MUST be computed dynamically from the wall-clock time since the server started.

**`GET /api/events`** — MUST return an SSE (text/event-stream) stream. Each SSE event MUST carry one serialized `SchedulerEvent` as its data payload. The stream MUST remain open until the client disconnects. The server MUST send SSE keep-alive pings.

### LiveState

`LiveState` MUST contain:
- `goal: String` — the research goal for the current run
- `rounds: u32` — number of scheduler rounds completed so far
- `elapsed_secs: f64` — wall-clock seconds since server start (computed dynamically)
- `active_nodes: HashSet<String>` — node IDs whose activations are currently in flight
- `finished: bool` — whether the run has halted
- `node_outputs: HashMap<String, Vec<serde_json::Value>>` — latest outputs per node; keyed by node ID; each value is an array of `{port, kind, data}` objects

### track_live_state

`track_live_state(rx, live)` MUST subscribe to the broadcast channel and fold incoming `SchedulerEvent`s into the `LiveState` according to these rules:
- `ActivationStarted { node_id }` → insert `node_id` into `active_nodes`
- `ActivationCompleted { node_id, outputs }` → remove `node_id` from `active_nodes`; if `outputs` is non-empty, replace `node_outputs[node_id]` with `outputs`
- `ActivationFailed { node_id }` → remove `node_id` from `active_nodes`
- `CycleCompleted { round }` → set `rounds = round`
- `RunHalted` → set `finished = true`
- All other events → no state change required

`track_live_state` MUST be spawned as a background task. The returned `JoinHandle` MUST be kept alive for the duration of the run.

### Event broadcast

The scheduler's event channel is a broadcast channel (`tokio::sync::broadcast`). The session MUST call `set_event_broadcaster` with the broadcast sender before starting a run. The server subscribes via `broadcast::Receiver`.

## Rationale

The server is intentionally simple — three endpoints, no authentication. It is designed for local developer use and for the companion `EurekaUI` macOS application that connects to `http://127.0.0.1:7773`.
