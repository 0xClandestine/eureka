## Abstract

Defines the HTTP server: base URL, the observability endpoints, the run management REST API, `LiveState` structure, SSE event stream, and the `track_live_state` background task that folds scheduler events into the live snapshot.

## Specification

### Server binding

The server MUST bind to `http://127.0.0.1:{port}` where `port` is configurable via the CLI (`--port`). The default port is `7773`. When `--port 0` is passed, the server MUST be disabled (no socket opened, no tasks spawned).

CORS MUST be enabled for all origins.

### Observability endpoints

**`GET /api/graph`** — MUST return the `GraphSpec` as a JSON body. The spec is static for the lifetime of the server process.

**`GET /api/state`** — MUST return a `LiveState` JSON snapshot. `elapsed_secs` MUST always be computed dynamically from the wall-clock time since the server started, regardless of whether the run has finished.

**`GET /api/run`** — MUST return the durable `RunRecord` for the current run when a `RunStore` and run ID are configured. MUST return `404` otherwise.

**`GET /api/events/history`** — MUST return the full durable event history as a JSON array of `RunEvent` when a `RunStore` and run ID are configured. MUST return `404` otherwise.

**`GET /api/events`** — MUST return an SSE (text/event-stream) stream. Each SSE event MUST carry one serialized `SchedulerEvent` as its data payload. The stream MUST remain open until the client disconnects. The server MUST send SSE keep-alive pings (interval: 15 seconds, text: `"ping"`).

**`GET /api/metrics`** — MUST return a JSON array of `RoundMetrics` representing per-round cost, token, and Elo time series.

### Run management endpoints

All run management endpoints require a `RunManager` to be configured. When absent they MUST return `404`.

**`POST /runs`** — create and immediately start a new managed run. Body: `{ "goal": <json> }`. MUST return `202 Accepted` with body `{ "id": "<uuid>" }`.

**`GET /runs`** — list all runs known to the `RunManager`. MUST return a JSON array of `RunRecord`.

**`GET /runs/{id}`** — return the `RunRecord` for one run. MUST return `404` when the run does not exist.

**`POST /runs/{id}/pause`** — request a pause on an active run. MUST return `202 Accepted` on success, `409 Conflict` on failure.

**`POST /runs/{id}/resume`** — resume a paused run from its latest checkpoint. MUST return `202 Accepted` on success, `409 Conflict` on failure.

**`POST /runs/{id}/cancel`** — cancel an active run. MUST return `202 Accepted` on success, `409 Conflict` on failure.

**`POST /runs/{id}/input`** — inject a typed artifact into a paused run. Body: `{ "node_id": string, "port": string, "artifact": Artifact }`. MUST return the updated `RunCheckpoint` on success, `409 Conflict` on failure.

**`GET /runs/{id}/checkpoint`** — load the latest durable checkpoint for a run. MUST return `404` when no checkpoint exists.

**`GET /runs/{id}/events`** — load the durable scheduler event history for a run. MUST return a JSON array of `RunEvent`.

### LiveState

`LiveState` MUST contain:
- `goal: String` — the research goal for the current run
- `run_id: Option<String>` — run identifier for lifecycle controls (pause/resume/cancel)
- `rounds: u32` — number of scheduler rounds completed so far
- `elapsed_secs: f64` — wall-clock seconds since server start (computed dynamically)
- `active_nodes: HashSet<String>` — node IDs whose activations are currently in flight
- `finished: bool` — whether the run has halted
- `node_outputs: HashMap<String, Vec<serde_json::Value>>` — latest outputs per node; keyed by node ID; each value is an array of `{port, kind, data}` objects
- `round_metrics: Vec<RoundMetrics>` — per-round cost, token, and Elo time series; populated at each `CycleCompleted`
- `live_tokens: u64` — cumulative tokens consumed; overridden from the per-request atomic counter when configured
- `live_cost_usd: f64` — cumulative cost in USD; overridden from the per-request cost mutex when configured

### track_live_state

`track_live_state(rx, live)` MUST subscribe to the broadcast channel and fold incoming `SchedulerEvent`s into the `LiveState` according to these rules:
- `ActivationStarted { node_id }` → insert `node_id` into `active_nodes`
- `ActivationCompleted { node_id, outputs, usage }` → remove `node_id` from `active_nodes`; if `outputs` is non-empty, replace `node_outputs[node_id]` with `outputs`; accumulate `usage.total_tokens` into `round_tokens` and `usage.cost_usd` into `round_cost`; if `node_id == "ranking"`, extract the top hypothesis score from the `"top"` port output
- `ActivationFailed { node_id }` → remove `node_id` from `active_nodes`
- `CycleCompleted { round }` → set `rounds = round`; record a `RoundMetrics` entry with the accumulated round tokens, round cost, total cumulative tokens, total cumulative cost, and the pending top score (if any); reset the round accumulators to zero
- `RunHalted { total_rounds }` → set `rounds = total_rounds`; set `finished = true`
- `RunPaused { round }` → set `rounds = round`; leave `finished = false`
- All other events (e.g. `ToolCalled`) → no state change required

`track_live_state` MUST be spawned as a background task. The returned `JoinHandle` MUST be kept alive for the duration of the run.

### RoundMetrics

`RoundMetrics` is a per-round cost and quality measurement. It MUST contain:
- `round: u32` — round number (0-based)
- `elapsed_secs: f64` — wall-clock seconds elapsed when the round completed
- `tokens: u64` — tokens consumed during this round
- `cost_usd: f64` — USD cost incurred during this round
- `total_tokens: u64` — cumulative tokens through this round
- `total_cost_usd: f64` — cumulative cost through this round
- `top_score: Option<f64>` — highest hypothesis score from the ranker at this round (Elo rating)

### Live per-request counter override

The `ServerState` MAY carry `live_tokens: Option<Arc<AtomicU64>>` and `live_cost: Option<Arc<Mutex<f64>>>` shared atomics. When present, `GET /api/state` MUST override `snapshot.live_tokens` and `snapshot.live_cost_usd` with the values read from the atomics, so the snapshot reflects real-time cumulative usage from per-request increments rather than only event-driven updates.

### Static frontend serving

When `spec.frontend` is `Some(path)`, the server MUST attach a `tower_http::services::ServeDir` fallback route at `/` with `append_index_html_on_directories(true)`. API routes (`/api/*`, `/runs/*`) take priority over the static file fallback.

### Event broadcast

The scheduler's event channel is a broadcast channel (`tokio::sync::broadcast`). The session MUST call `set_event_broadcaster` with the broadcast sender before starting a run. The server subscribes via `broadcast::Receiver`.

## Rationale

The server has no authentication and is designed for local developer use. The run management endpoints are optional — they require a `RunManager` and return `404` when one is not configured, so the server can be deployed in a minimal observability-only mode.
