## Abstract

Defines the persistence layer: the `RunRecord` lifecycle type, the three storage traits (`RunStore`, `CheckpointStore`, `EventStore`), the composite `RunPersistence` trait, the versioned `RunRepository` trait, checkpoint types, error types, optimistic concurrency via `Revision`, and the environment contract version.

## Specification

### RunRecord

A `RunRecord` captures the lifecycle metadata for one Eureka execution. It MUST contain:
- `id: uuid::Uuid` — the unique run identifier
- `graph: String` — the manifest path used for this run
- `goal: serde_json::Value` — the initial goal value
- `status: RunStatus`
- `revision: Revision` — monotonic revision maintained by the persistence backend; defaults to `0`
- `stats: Option<RunStats>` — populated when the run completes, pauses, or fails
- `error: Option<String>` — populated on failure or cancellation

`RunRecord::new(id, graph, goal)` MUST initialize with `status = RunStatus::Created`.

### RunStatus

`RunStatus` MUST be one of: `Created`, `Running`, `Paused`, `Completed`, `Failed`, `Cancelled`.

- `Created` — record has been created but execution has not started
- `Running` — execution is currently in progress
- `Paused` — execution was paused by an external signal
- `Completed` — execution completed normally
- `Failed` — execution failed
- `Cancelled` — execution was cancelled

Serialization uses `snake_case` (e.g., `"created"`, `"running"`).

### RunFilter

`RunFilter` is used when listing persisted runs. It MUST contain:
- `status: Option<RunStatus>` — restrict results to one lifecycle status
- `limit: Option<usize>` — maximum number of records to return

### RunOutput

`RunOutput` represents an artifact emitted by a terminal (sink) node. It MUST contain:
- `node_id: String` — node that emitted the artifact
- `port: String` — output port that emitted the artifact
- `round: u32` — scheduler round in which it was emitted
- `artifact: Artifact`

### RunCheckpoint

`RunCheckpoint` is the serializable scheduler state used for durable recovery. It MUST contain:
- `run_id: uuid::Uuid`
- `revision: Revision` — monotonic checkpoint revision
- `graph_hash: String` — hash of the graph manifest/topology used to create the checkpoint
- `config_hash: String` — hash of runtime configuration used to create the checkpoint
- `round: u32` — current synchronized scheduler round
- `round_pending: HashMap<u32, usize>` — outstanding activation count by round
- `pending_inputs: Vec<PendingInput>` — artifacts buffered for not-yet-ready nodes
- `ready_activations: Vec<ActivationSnapshot>` — activations ready to dispatch at this boundary
- `stats: RunStats` — statistics accumulated through this boundary
- `outputs: Vec<RunOutput>` — terminal artifacts emitted through this boundary
- `reason: CheckpointReason` — why this checkpoint was written

`RunCheckpoint::new(run_id, graph_hash, config_hash)` MUST initialize with `revision = Revision(0)`, `round = 0`, `reason = CheckpointReason::RoundCompleted`, and all collections empty.

`RunCheckpoint::inject_input(node_id, port, artifact)` MUST add a `PendingInput` at the current `round`. It MUST return `PersistenceError::InputConflict` if an input already exists for the same `(node_id, port)` pair at the same round.

### CheckpointReason

`CheckpointReason` MUST be one of: `RoundCompleted`, `Pause`, `Cancellation`, `Completion`, `InputAccepted`.

Serialization uses `snake_case`.

### PendingInput

`PendingInput` represents an input artifact waiting for a node activation. It MUST contain:
- `node_id: String`
- `round: u32`
- `port: String`
- `artifact: Artifact`

### ActivationSnapshot

`ActivationSnapshot` represents a ready activation captured at a scheduler boundary. It MUST contain:
- `node_id: String`
- `round: u32`
- `inputs: Vec<PortMsg>`

### RunStore

`RunStore` is the compatibility persistence interface. It MUST provide:
- `async save(record)` — insert or replace a record; returns `std::io::Result<()>`
- `async get(id)` — load by UUID; returns `Ok(None)` if absent
- `async delete(id)` — delete by UUID
- `async list()` — list all records

### CheckpointStore

`CheckpointStore` provides durable scheduler checkpoints for resume. It MUST provide:
- `async save_checkpoint(checkpoint, expected: Option<Revision>)` — save a checkpoint; MUST apply optimistic concurrency if `expected` is `Some`; returns the updated checkpoint with incremented revision
- `async load_checkpoint(run_id)` — load the latest checkpoint for a run; `Ok(None)` if absent
- `async delete_checkpoint(run_id)` — delete the checkpoint

### EventStore

`EventStore` provides an append-only, ordered event history. It MUST provide:
- `async append_event(run_id, event: serde_json::Value)` — append one serialized `SchedulerEvent`; MUST assign a monotonically increasing `sequence` within the run; returns the stored `RunEvent`
- `async load_events(run_id)` — return all events in sequence order
- `async delete_events(run_id)` — delete all events for a run

### RunEvent

A `RunEvent` MUST contain:
- `run_id: uuid::Uuid`
- `sequence: u64` — monotonically increasing within the run
- `timestamp_ms: u64` — Unix timestamp in milliseconds
- `event: serde_json::Value` — serialized `SchedulerEvent`

### RunPersistence

`RunPersistence` is a marker supertrait combining `RunStore + CheckpointStore + EventStore`. Any type implementing all three automatically implements `RunPersistence`.

`SqliteRunPersistence` is the canonical implementation. It MUST be opened via `SqliteRunPersistence::open(path)`. The convenience function `open_persistence(path)` returns `Arc<dyn RunPersistence>`.

### RunRepository

`RunRepository` is the versioned persistence interface used by run managers and recovery code. It MUST provide:
- `async create(record)` — insert a new run at revision zero; MUST return `PersistenceError::AlreadyExists` if the ID already exists
- `async get_versioned(id)` — load by UUID with current revision; `Ok(None)` if absent
- `async save_if_revision(record, expected)` — replace a run only when its current revision equals `expected`; MUST return `PersistenceError::RevisionConflict` on mismatch
- `async list(filter)` — list records matching a `RunFilter`
- `async delete_versioned(id)` — delete a run; MUST return `PersistenceError::NotFound` if absent

### Revision

`Revision` is a newtype over `i64` with transparent serialization. It MUST be monotonically increasing per record. It MUST start at `0` for new records. The persistence backend MUST increment the revision on every successful save.

### PersistenceError

The following error variants MUST exist:
- `NotFound(uuid::Uuid)` — record does not exist
- `AlreadyExists(uuid::Uuid)` — attempt to create a duplicate
- `RevisionConflict { run_id, expected, actual }` — optimistic concurrency violation
- `Io(std::io::Error)` — storage I/O error
- `Serialization(String)` — malformed persisted record
- `InputConflict { node_id, port }` — external artifact injection conflict

### Database environment contract

`DATABASE_SCHEMA_VERSION: u32 = 1` is the current version of the runtime database environment contract, exposed to subprocesses via `EUREKA_DB_SCHEMA_VERSION`. Subprocesses MUST reject environments with incompatible schema versions.

Plugins MUST use their own table namespaces within the per-run database. Plugins MUST NOT read from or write to tables prefixed with `eureka_` — those are owned by the runtime.

`RunEnvironment` is a capability descriptor (not a live database connection) passed to subprocesses. It carries `session_id`, `db_path`, and `database_schema_version`.
