## Abstract

Defines the `PortRegistry`, `ValidationResult`, and `validate_graph` function that enforce structural correctness of a `GraphSpec` before any node is executed.

## Specification

### PortRegistry

A `PortRegistry` maps node kind strings to their `PortSpec`. It MUST be keyed by the `kind` field of `GraphNodeSpec`, not the `id` field. Multiple nodes sharing the same `kind` share one registry entry.

`PortRegistry::register(kind, spec)` MUST insert or replace the entry for `kind`.

`PortRegistry::get(kind)` MUST return the registered `PortSpec` for `kind`, or `None` if not registered.

### ValidationResult

`ValidationResult` MUST contain:
- `valid: bool` — `true` if and only if `errors` is empty
- `errors: Vec<GraphError>`

### validate_graph

`validate_graph(spec, registry)` MUST run the following checks in order, collecting all errors before returning:

**Check 0 — Unknown node references:** Every node ID referenced in `edges` (as `from_node` or `to_node`) MUST exist in `spec.nodes`. If any referenced node is absent, validation MUST stop and return immediately with the collected `UnknownNode` errors before proceeding to further checks.

**Check 1 — Port kind match:** For every edge where both `from_node` and `to_node` have registered port specs, the output kind at `from_port` MUST equal the input kind at `to_port`. If either port is not found in the registry entry, an `UnknownPort` error MUST be added. Kind mismatch MUST produce a `PortKindMismatch` error.

**Check 2 — No dangling required inputs:** For every node with a registered port spec, every required input port MUST have at least one inbound edge. Exception: a required input port that accepts `"Goal"` artifacts MUST be exempt from this check, because goal injection substitutes for an inbound edge (see SPEC-0012).

**Check 3 — Reachability:** Every node MUST be reachable from at least one source node via forward BFS over all edges. Source candidates are:
1. Nodes whose registered port spec declares any input of kind `"Goal"`. If no such nodes exist, fall back to:
2. Nodes with no inbound edges at all.

If no source nodes are found, an `UnreachableNode` error MUST be added. Unreachable nodes (not visited in BFS from sources) MUST produce an `UnreachableNode` error each.

**Check 3b — Unknown node kinds:** If the registry is non-empty, every node kind in the spec MUST be registered. Unregistered kinds MUST produce an `UnknownNode` error.

**Check 4 — Governed cycles:** Every strongly connected component (SCC) with more than one node, or with exactly one node that has a self-loop, MUST contain at least one governor node. A governor node is a node whose registered port spec declares an output port named `"halt"`. An SCC without a governor MUST produce an `UngovernedCycle` error.

SCCs MUST be detected using Tarjan's algorithm.

**Check 5 — Sink presence:** If the registry is non-empty, at least one node MUST produce an output whose `ArtifactKind` is not consumed as an input by any registered node kind. A graph with no such terminal output MUST produce a `MissingSink` error.

The function MUST return `ValidationResult::valid()` if `errors` is empty, or `ValidationResult::invalid(errors)` otherwise.

### Validation timing

`validate_graph` MUST be called before any node is constructed and before any LLM or subprocess call is made.
