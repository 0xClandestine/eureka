## Abstract

Defines the subprocess protocol for control nodes: the call envelope written to stdin, the emit envelopes read from stdout, the environment variables injected into the subprocess, the subprocess runner behavior, and the `ControlNodeDef` structure.

## Specification

### ControlNodeDef

A `ControlNodeDef` is the runtime description of a control node. It MUST contain:
- `name: String` — display name for error messages
- `work_dir: PathBuf` — absolute working directory for the subprocess
- `command: Vec<String>` — subprocess argv
- `inputs: Vec<PortDef>`
- `outputs: Vec<PortDef>`
- `timeout_secs: u32`

### Call envelope (stdin)

When the scheduler activates a control node, the framework MUST write exactly one JSON object to the subprocess's stdin. The object MUST contain:
- `port: String` — the first available input's port name (backward-compatible field)
- `artifact: { kind: String, data: Value }` — the first available input's artifact (backward-compatible field)
- `inputs: Array` — one object per available input, each containing `port` and `artifact`; the array is ordered by the sequence in which inputs arrived

A subprocess that reads only `envelope["artifact"]` and `envelope["port"]` MUST continue to work correctly when a single input is present (backward compatibility). A subprocess that needs all inputs MUST read `envelope["inputs"]`.

If no inputs are available, `port` MUST be `""`, `artifact.kind` MUST be `""`, `artifact.data` MUST be `null`, and `inputs` MUST be `[]`.

### Emit envelope (stdout)

The subprocess MUST write zero or more emit envelopes to stdout, one per line, each as a JSON object. Each emit envelope MUST contain:
- `port: String` — the output port name
- `artifact: { kind: String, data: Value }` — the artifact to emit

Blank lines MUST be ignored. Any line that is not valid JSON MUST cause `NodeError::Internal`.

The subprocess MUST exit with code `0` to signal success. A non-zero exit code MUST cause `NodeError::Internal`.

### Environment variables

The framework MUST set the following environment variables for every control node subprocess invocation:
- `EUREKA_SESSION_ID` — the session UUID string
- `EUREKA_NODE_ID` — the node ID from the manifest
- `EUREKA_ROUND` — the current round number as a decimal string
- `EUREKA_CONFIG` — the node's `config` value JSON-serialized; `"{}"` if null
- `EUREKA_DB_SCHEMA_VERSION` — the database contract version integer (`1` at this time)
- `EUREKA_DB_NAMESPACE` — the node ID (the subprocess's plugin namespace; MUST NOT grant access to runtime-owned tables)
- `EUREKA_DB_PATH` — the absolute path to the per-run SQLite database; MUST be set only when a database path is available; omitted otherwise

These same variables MUST be injected into agent tool (`CommandTool`) subprocesses.

### Subprocess runner

`run_subprocess(binary, args, current_dir, envs, stdin_data, timeout_secs)` MUST:
1. Spawn `binary` with `args` and `kill_on_drop(true)`
2. If `current_dir` is `Some(path)`, set the subprocess working directory to `path`
3. Set all key-value pairs in `envs` as environment variables
4. Concurrently: write `stdin_data` to stdin, read all stdout, read all stderr
5. Wait for the subprocess to exit, up to `timeout_secs` wall-clock seconds
6. On timeout: kill the subprocess explicitly and await reaping; return `ControlError::Timeout`
7. Cap stdout at `MAX_OUTPUT_BYTES` (65536 bytes); if capped, append `"\n[truncated]"` to the captured stdout
8. Capping MUST NOT split a multi-byte UTF-8 sequence

The runner MUST use `floor_char_boundary` (or equivalent) to find the safe truncation point.

### NodeUsage

`ControlNode::process` MUST return `NodeUsage::default()` (all zeros). Control nodes do not consume LLM tokens.

## Rationale

The backward-compatible `port`/`artifact` fields allow existing single-input scripts to continue working without modification. Scripts that need all inputs read from the `inputs` array.

The subprocess is killed rather than abandoned on timeout to prevent orphaned processes from accumulating.
