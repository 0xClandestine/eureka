## Abstract

Defines the `Artifact` type and `ArtifactKind` alias — the typed envelope for all data flowing through the graph.

## Specification

### ArtifactKind

`ArtifactKind` is a type alias for `String`. It is not an enum. The set of valid kind strings is open and defined entirely by agent and control node definitions in the YAML manifest. The runtime MUST NOT assign semantic meaning to any particular kind string except `"Goal"`, which is reserved for the initial goal artifact injected by the session (see SPEC-0012).

### Artifact

An `Artifact` is a value of type `Artifact { kind: ArtifactKind, data: serde_json::Value }`.

`kind` MUST be a non-empty string.

`data` is an opaque JSON value. The runtime MUST NOT interpret or validate `data`; interpretation is the responsibility of the receiving node.

`Artifact` MUST implement `Clone`, `PartialEq`, `Eq`, `Debug`, `Serialize`, and `Deserialize`.

`Artifact::new<T: Serialize>(kind, value)` MUST serialize `value` to a `serde_json::Value` and return an `Artifact` with that kind and data. It MUST return an error if serialization fails.

`Artifact::deserialize_as<T: Deserialize>()` MUST deserialize `self.data` into `T`. It MUST return an error if deserialization fails.

### Kind matching

The runtime uses `kind` exclusively as a string equality check at edge endpoints: the `ArtifactKind` on an output port MUST equal the `ArtifactKind` on the connected input port. No other kind logic is performed by the runtime.

## Rationale

Making `ArtifactKind` a plain `String` rather than an enum removes all domain knowledge from the runtime. Adding a new artifact kind requires only a manifest change, not a Rust change.
