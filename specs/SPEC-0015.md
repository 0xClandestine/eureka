## Abstract

Defines `EngineError`, the top-level error type for the eureka library crate. All public session, manager, and builder APIs that can fail MUST return `Result<_, EngineError>`.

## Specification

### EngineError

`EngineError` is derived with `thiserror::Error` and `Debug`. It MUST have exactly the following variants:

| Variant | Source | Display |
|---------|--------|---------|
| `Graph(GraphError)` | `#[from] crate::graph::spec::GraphError` | `"Graph error: {0}"` |
| `Config(ConfigError)` | `#[from] crate::config::ConfigError` | `"Config error: {0}"` |
| `Scheduler(String)` | — | `"Scheduler error: {0}"` |
| `NodeCreation(String)` | — | `"Node creation error: {0}"` |
| `UnknownNodeKind(String)` | — | `"Unknown node kind: {0}"` |
| `Run(String)` | — | `"Run error: {0}"` |
| `Store(String)` | — | `"Store error: {0}"` |

### Variant semantics

- `Graph` — wraps a graph topology or specification error; automatic `From<GraphError>` conversion
- `Config` — wraps a configuration loading or validation error; automatic `From<ConfigError>` conversion
- `Scheduler` — wraps a scheduler-level error string (the scheduler's own error type is mapped here at session boundaries)
- `NodeCreation` — the runtime could not construct a node from its manifest spec (e.g., prompt loading failed, unknown LLM client)
- `UnknownNodeKind` — a manifest references a node kind not registered in the node registry
- `Run` — a lifecycle management error (run not found, wrong status, signalling failed, etc.)
- `Store` — a persistence backend error (mapped from `PersistenceError` or `io::Error`)

### Mapping conventions

Code that converts lower-level errors to `EngineError` MUST use `.map_err(|e| EngineError::Store(e.to_string()))` for persistence errors and `.map_err(|e| EngineError::Scheduler(e.to_string()))` for scheduler errors. These conventions keep `EngineError` free of generic parameters and allow it to cross `dyn` boundaries.
