## Abstract

Defines the Retrieval-Augmented Generation (RAG) subsystem: the `RagConfig` and `EmbeddingProvider` configuration types, the `RagDocument` store schema, the `RagIndexer` artifact-to-vector pipeline, the `RagIndexHandle` type-erased query handle, the one-time `register_sqlite_vec` extension registration, and the `build_rag_components` entry point.

## Specification

### EmbeddingProvider

`EmbeddingProvider` enumerates supported embedding backends. It MUST be one of:

| Variant    | Serde value   | Required env var        | Notes |
|------------|---------------|-------------------------|-------|
| `OpenAI`   | `"openai"`    | `OPENAI_API_KEY`        | |
| `Cohere`   | `"cohere"`    | `COHERE_API_KEY`        | Uses `"search_document"` input type for indexing |
| `Ollama`   | `"ollama"`    | `OLLAMA_BASE_URL`       | `embedding_ndims` is REQUIRED |
| `VoyageAI` | `"voyageai"`  | `VOYAGE_API_KEY`        | `embedding_ndims` overrides model default |
| `Gemini`   | `"gemini"`    | `GEMINI_API_KEY`        | Dimensions inferred from model name |
| `Together` | `"together"`  | `TOGETHER_API_KEY`      | `embedding_ndims` SHOULD be set |
| `Llamafile`| `"llamafile"` | `LLAMAFILE_API_BASE_URL`| `embedding_ndims` SHOULD be set |
| `OpenRouter`| `"openrouter"`| `OPENROUTER_API_KEY`   | `embedding_ndims` optional |

### RagConfig

`RagConfig` is placed in the `[rag]` section of `eureka.toml`. It MUST contain:

- `enabled: bool` — whether RAG is active for this run
- `embedding_provider: EmbeddingProvider`
- `embedding_model: String` — provider-specific model name
- `top_k: usize` — number of top documents retrieved per agent turn
- `index_kinds: Vec<String>` — artifact kinds to index; an empty list means all kinds are indexed
- `agent_ids: Vec<String>` — agent node IDs to attach dynamic context to; an empty list means all agents
- `session_scoped: bool` — restrict retrieval to the current session only; defaults to `true`
- `embedding_ndims: Option<usize>` — embedding output dimensions; REQUIRED for Ollama; optional for other providers
- `embedding_cost_per_million_tokens: Option<f64>` — cost per million tokens for the embedding model; when set, embedding tokens are estimated (chars/4) and accumulated into the per-request live cost counter

### RagDocument

`RagDocument` is the schema stored in the `sqlite-vec` vector store. It MUST contain:

- `id: String` — unique document identifier formatted as `"<node_id>:r<round>:<chunk_index>"`
- `text: String` — embeddable text chunk from the artifact payload (the `#[embed]`-marked field)
- `metadata: serde_json::Value` — JSON provenance with keys: `node_id`, `round`, `kind`, `session_id`

The backing SQLite table name MUST be `"eureka_rag_documents"` with columns `id TEXT PRIMARY KEY`, `text TEXT`, `metadata JSON`.

### NodeRagConfig

`NodeRagConfig` is an optional per-agent configuration placed under each agent's `rag:` key in the YAML manifest. It MAY contain:

- `enabled: bool` — if `false`, this agent neither receives RAG context nor has its outputs indexed; defaults to `true`
- `top_k: Option<usize>` — overrides the global `RagConfig::top_k` for this agent's dynamic context query; absent means use global value
- `index_path: Option<String>` — dot-notation path to extract index text from the artifact payload; supports `field[*].subfield` to fan out over arrays; absent means fall back to `chunk_artifact` (full JSON serialisation)
- `inject_format: Option<String>` — template for the text stored in the vector index; `{{text}}` is substituted with the extracted text; absent means store raw extracted text

### Chunking strategy

`chunk_artifact(kind, data)` is the fallback used when no `index_path` is configured. It MUST chunk an artifact payload as follows:
- If `data` is a JSON array: produce one chunk per element (serialized to a JSON string); skip empty strings
- Otherwise: serialize the entire value as a single JSON string; skip if empty

The `kind` parameter is reserved for future per-kind strategy overrides and MUST NOT be used to alter behavior in the current implementation.

`extract_texts(path, data)` MUST extract leaf text values from `data` following a dot-notation path:
- Split `path` on `'.'`; for each segment, navigate into the current set of JSON values
- A segment ending with `[*]` (wildcard) iterates the matched array and fans out to all elements
- String leaves are returned as-is; non-string non-null leaves are JSON-serialised; null leaves and empty strings are dropped
- Returns a flat `Vec<String>` of all matched, non-empty leaf values

### RagIndexer

`RagIndexer` receives artifact emissions from the scheduler and embeds them asynchronously. It MUST:
- Hold an `index_kinds: HashSet<String>` filter; an empty set means all kinds are accepted
- Hold a `session_id: String` embedded in every document's metadata
- Hold a `node_configs: HashMap<String, NodeRagConfig>` for per-node extraction and formatting
- Provide `index_artifact(node_id, round, artifact)` which:
  1. Returns `Ok(())` early if `index_kinds` is non-empty and does not contain `artifact.kind`
  2. Returns `Ok(())` early if the node has a `NodeRagConfig` with `enabled = false`
  3. Calls `extract_texts(index_path, data)` if the node has a configured `index_path`; otherwise calls `chunk_artifact`
  4. Returns `Ok(())` early if no chunks were produced
  5. Applies `inject_format` template substitution if configured
  6. Constructs `RagDocument` values and calls the embed-and-insert closure
- The embed-and-insert invocation in the scheduler MUST be detached via `tokio::spawn`; RAG indexing failures MUST be logged as warnings and MUST NOT stop graph execution

`RagIndexer::with_live_counters(tokens, cost, cost_per_million)` MAY attach shared atomic counters for real-time cost observability. When attached, `index_artifact` MUST estimate tokens as `sum(chunk_text.len() / 4)` across all chunks, atomically increment `live_tokens`, and add `(estimated_tokens * cost_per_million / 1e6)` to `live_cost` before the async embed call, so the UI updates without waiting for embedding to complete.

### RagIndexHandle

`RagIndexHandle` is a newtype `(Arc<dyn VectorStoreIndexDyn + Send + Sync + 'static>)` that type-erases the embedding model generic parameter. The `'static` bound is required because the handle is stored across await points. It MUST be cheaply cloneable (clone just bumps the `Arc` refcount).

Querying is performed by passing `RagIndexHandle` to `rig-core`'s `AgentBuilder::dynamic_context`. The handle MUST expose the underlying `VectorStoreIndexDyn` for this purpose.

### register_sqlite_vec

`register_sqlite_vec()` MUST register the `sqlite-vec` extension as a SQLite auto-extension via `sqlite3_auto_extension`. It MUST execute exactly once per process regardless of how many times it is called (guarded by `OnceLock`). It MUST be called before the first `rusqlite::Connection::open`.

The single `unsafe` block required for the raw C API call MUST be isolated to `crates/eureka/src/rag/init.rs`.

### build_rag_components

`build_rag_components(cfg: &RagConfig, db_path: &Path, session_id: &str, live_tokens: Option<Arc<AtomicU64>>, live_cost: Option<Arc<Mutex<f64>>>)` is the single entry point for the RAG subsystem. It MUST:
1. Match on `cfg.embedding_provider` and construct the concrete embedding model for that provider
2. Open a `tokio-rusqlite` connection to `db_path`
3. Initialize a `SqliteVectorStore<E, RagDocument>` against that connection
4. Clone the store so the insert path and query path share the same underlying connection handle
5. Build a type-erased `RagIndexHandle` from the query index
6. Build a type-erased embed-and-insert closure for `RagIndexer`
7. If `live_tokens` and `live_cost` are both `Some`, attach them to the indexer via `with_live_counters()` together with `cfg.embedding_cost_per_million_tokens`
8. Return `(RagIndexHandle, Arc<RagIndexer>)`

All generics over the embedding model type MUST be erased inside `build_rag_components`. Callers MUST only see `RagIndexHandle` and `Arc<RagIndexer>`.

### Session integration

The session lazily initializes RAG on first run when `config.rag.enabled` is `true` and a `db_path` is available. If RAG initialization fails, the session MUST log a warning and continue without RAG — it MUST NOT fail the run.

If `db_path` is absent but `rag.enabled` is `true`, the session MUST log a warning and run without RAG.

The `RagIndexHandle` is passed to qualifying agents' `AgentBuilder::dynamic_context`. An agent qualifies when:
1. `rag.agent_ids` is empty (all agents) OR the agent's ID appears in `rag.agent_ids`, AND
2. The agent has no `NodeRagConfig`, OR its `NodeRagConfig.enabled` is `true`

When a `NodeRagConfig` is present and `top_k` is set, that value MUST be used instead of the global `RagConfig::top_k` for that agent's `dynamic_context` call.
