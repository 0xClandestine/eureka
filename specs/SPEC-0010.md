# SPEC-0010: Agent Node Protocol

| Field      | Value            |
|------------|------------------|

## Abstract

Defines the LLM agent node: the `AgentDef` and `ToolDef` structures, the `LlmClient` trait and its `RigClient` implementation, and the agentic loop protocol including multi-input formatting, output port splitting, and the reserved `submit` tool.

## Specification

### AgentDef

An `AgentDef` is the fully resolved runtime representation of an LLM agent. It MUST contain:
- `name: String` — matches the node ID from the manifest; used as the `kind` string in the registry
- `description: Option<String>` — optional human-readable description
- `preamble: String` — the loaded system prompt text
- `inputs: Vec<PortDef>` — input port declarations
- `outputs: Vec<PortDef>` — output port declarations
- `config: AgentConfig` — LLM configuration (`temperature`, `max_iterations`, `workers`)
- `output_schema: serde_json::Value` — JSON Schema the `submit` call MUST conform to
- `tools: Vec<ToolDef>` — shell tools available in the loop; MUST NOT include a tool named `"submit"`
- `mcp_servers: Vec<McpServerDef>` — MCP servers connected at session-build time; may be empty

`AgentDef::to_port_spec()` MUST return a `PortSpec` built from `inputs` and `outputs` via `PortSpec::from_defs`.

### ToolDef

A `ToolDef` declares one shell tool available to the agent. It MUST contain:
- `name: String` — tool name shown to the LLM; MUST NOT be `"submit"`
- `description: String`
- `command: Vec<String>` — subprocess argv; `command[0]` is the binary
- `args_schema: serde_json::Value` — JSON Schema for LLM-provided arguments
- `timeout_secs: u32` — subprocess timeout; defaults to `30`

The framework MUST reject any `ToolDef` whose `name` is `"submit"`. The `submit` name is reserved for the terminal output tool injected by the framework.

### LlmClient trait

`LlmClient` is a `Send + Sync` async trait with the method:

```
run_agent_loop(preamble, output_schema, tools, initial_message,
               max_iterations, temperature, node_id, node_kind,
               round, work_dir, event_tx)
  -> Result<(serde_json::Value, NodeUsage), AgentError>
```

The method MUST run the agentic loop until the agent calls `submit` or `max_iterations` is exhausted. It MUST return the submitted JSON value and aggregated `NodeUsage`.

`run_agent_loop_with_environment` extends this with an additional `environment: &RunEnvironment` parameter that is forwarded to tool subprocesses (see SPEC-0011). It also accepts optional live-counter atomics (`live_tokens`, `live_input_tokens`, `live_output_tokens`, `live_cost`) for per-turn tracking. The default implementation delegates to `run_agent_loop` ignoring the environment and live counters; `RigClient` overrides it to pass the environment to `CommandTool` and the live counters to `LiveCounterHook`.

### RigClient

`RigClient<M>` is a `LlmClient` implementation backed by any rig `CompletionModel`. It wraps:
- `model: M` — the underlying completion model
- `pricing: Option<Pricing>` — per-input/per-output pricing for cost computation
- `rag: Option<(RagIndexHandle, usize)>` — optional RAG index and `top_k` for `dynamic_context`
- `mcp: Vec<McpConnection>` — live MCP server connections for the agent

`RigClient::with_rag(index, top_k)` MUST attach a RAG index so every agent turn retrieves the top-`k` most relevant documents via `AgentBuilder::dynamic_context`.

`RigClient::with_mcp(connections)` MUST attach pre-connected MCP server connections established from the agent's `mcp_servers` list.

### Retry behavior

`RigClient::run_agent_loop_with_environment` MUST retry transient provider failures up to **4 attempts** with exponential backoff: 1s, 2s, 4s between successive retries. Errors considered retryable include:
- `ProviderResponseError` with empty-body 200 OK (common OpenRouter transient failure)
- HTTP status 502, 503, or 529

If all attempts are exhausted, the method MUST return `AgentError::Provider` with a message indicating the failure count and last error.

Each retry attempt MUST create a fresh `Submit` store and `Usage` accumulator so that stale state from a failed attempt does not leak into the next.

### Agentic loop

The framework MUST inject into every agent loop a terminal tool named `submit` with a parameter schema equal to `output_schema`. The agent MUST call `submit` exactly once to terminate the loop.

The framework MUST build the final system preamble by appending to the user-supplied `preamble`:
1. The `output_schema` in a fenced JSON block under a `# Output Schema` heading (omitted if the schema is null or empty)
2. A turns budget instruction referencing `max_iterations`
3. If tools are present: a list of available tool names and a reminder to leave at least one turn for `submit`

If `max_iterations` is exhausted before `submit` is called, the loop MUST return `AgentError::ExtractionFailed`.

### Initial message formatting

**Single-input agents** (one declared input port): the `initial_message` MUST be the JSON-pretty-printed `data` of the first available `PortMsg`, ignoring the port name.

**Multi-input agents** (two or more declared input ports): the `initial_message` MUST be a concatenation of one section per available `PortMsg`, each section formatted as:
```
Port: <port_name>

<JSON-pretty-printed data>
```
Sections MUST be separated by `\n\n---\n\n`.

### Node-level parallelism

Parallelism is provided by replica expansion in the scheduler (controlled by `[agent] workers` in the runtime TOML config), not by internal LLM call fan-out. When the scheduler expands an agent node into replicas, each replica runs an independent agentic loop in parallel. `LlmAgentNode::process` always runs exactly one agentic loop per activation.

### Output port splitting

**Single-output agents** (one declared output port): the submitted JSON value is emitted as-is as the artifact `data` on that port.

**Multi-output agents** (two or more declared output ports): the submitted JSON value MUST be a JSON object. For each declared output port with name `P`, the artifact `data` on port `P` is `output_json[P]` if present, or `null` if absent. Every declared output port MUST produce exactly one `Emit`.

### NodeCtx

`NodeCtx` provides the runtime context for `LlmAgentNode::process`. In addition to the fields defined in SPEC-0005 (`node_id`, `node_kind`, `round`, `cancel`, `event_tx`), `NodeCtx` MUST carry the following optional live-counter fields:

- `live_tokens: Option<Arc<AtomicU64>>` — per-request total token counter
- `live_input_tokens: Option<Arc<AtomicU64>>` — per-request input token counter
- `live_output_tokens: Option<Arc<AtomicU64>>` — per-request output token counter
- `live_cost: Option<Arc<Mutex<f64>>>` — per-request cost tracker in USD

These fields are passed through to `RigClient` for per-turn accumulation by `LiveCounterHook`.

### Live per-request counter updates

Live counters (`live_tokens`, `live_input_tokens`, `live_output_tokens`, `live_cost`) are passed through `NodeCtx` to `run_agent_loop_with_environment` and then to `RigClient`, which wraps them in a `LiveCounterHook`. The `LiveCounterHook` fires on **every** LLM completion (`ModelTurnFinished`), incrementing the shared atomics per-turn — not just once per activation. `LlmAgentNode::process` does NOT directly update live counters; it only passes them through as context.

### CommandTool

`CommandTool` implements `ToolDyn` for a single `ToolDef`. When the LLM invokes the tool, `CommandTool` MUST:
1. Emit a `ToolCalled` scheduler event via `event_tx` if present; the event MUST include the full `args` JSON object
2. Interpolate `{{key}}` tokens in `command` with the LLM-provided argument values
3. Spawn the subprocess via `run_subprocess` with `work_dir` as the working directory
4. If exit code is 0: return `stdout` as a string
5. If exit code is non-zero: return a string of the form `"Error (exit <code>): <first 500 chars of stderr>"`
6. Emit a `ToolCompleted` scheduler event via `event_tx` if present; `result_preview` MUST be the first 16,000 characters of the return string; `success` MUST be `true` when exit code is 0

Token interpolation: `{{key}}` MUST be replaced by the string value of `args.key`, or by the JSON string representation for non-string values. If the key is absent, the placeholder MUST be replaced by an empty string.

`CommandTool` MUST pass the `RunEnvironment` to `run_subprocess` as environment variables (see SPEC-0011 for the variable names).
