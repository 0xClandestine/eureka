# SPEC-0014: Budget and Cost Tracking

## Abstract

Defines how node-level usage is accumulated into `RunStats`, how `RunStats` is checked against `Budget` backstops, and the four conditions that halt a run on budget exhaustion.

## Specification

### NodeUsage accumulation

After each activation completes, the scheduler MUST add the returned `NodeUsage` to the session-level `RunStats` accumulators:
- `RunStats.total_input_tokens += NodeUsage.input_tokens`
- `RunStats.total_output_tokens += NodeUsage.output_tokens`
- `RunStats.total_tokens += NodeUsage.total_tokens`
- `RunStats.total_cost_usd += NodeUsage.cost_usd`

`RunStats.elapsed_secs` MUST be updated from the wall-clock time since run start.

`RunStats.rounds_completed` MUST be incremented after each round drains (see SPEC-0009).

### Budget backstop evaluation

The scheduler runs a 100 ms ticker concurrently with the main activation loop. On each tick it MUST call `RunStats::is_budget_exhausted(budget)`. Because the ticker fires independently of round boundaries, the budget may be declared exhausted mid-round; the scheduler then cancels all in-flight activations and halts.

`is_budget_exhausted` MUST return `Some(reason_string)` if any of the following conditions holds, checked in this order:
1. `total_cost_usd >= budget.max_cost_usd`
2. `total_tokens >= budget.max_tokens`
3. `elapsed_secs >= budget.max_wallclock`
4. `rounds_completed >= budget.max_rounds`

`is_budget_exhausted` MUST return `None` if none of the conditions holds.

When `Some` is returned, the scheduler MUST emit `RunHalted { reason, total_rounds }` and return the final `RunStats` as a successful result. Budget exhaustion MUST NOT be treated as an error.

### Cost tracking requirement

Cost (`NodeUsage.cost_usd`) is always `0.0` when `ProviderConfig.pricing` is `None`. In this case only the token, wallclock, and round backstops are effective. The cost backstop MUST still be checked, but will never fire unless pricing is configured.

### Governor vs. budget backstop

The graph's governor control node is the primary round controller. The `max_rounds` budget backstop is a hard safety cap that fires only if the governor fails to halt the run within the configured limit.
