## Abstract

Defines the `Session` type: how it is constructed, how a run is started or resumed, how the goal is injected, and how run records and lifecycle state are managed.

## Specification

### Session struct

The `Session` struct MUST contain the following fields:

| Field | Type |
|-------|------|
| `config` | `EurekaConfig` |
| `spec` | `GraphSpec` |
| `manifest` | `GraphManifest` |
| `graph_dir` | `PathBuf` |
| `session_id` | `uuid::Uuid` |
| `db_path` | `Option<PathBuf>` |
| `client_cache` | `HashMap<String, Arc<dyn LlmClient>>` |
| `default_model` | `String` |
| `stats` | `Option<RunStats>` |
| `event_broadcaster` | `Option<broadcast::Sender<SchedulerEvent>>` |
| `node_overrides` | `HashMap<String, BoxedNode>` |
| `checkpoint_store` | `Option<Arc<dyn CheckpointStore>>` |
| `event_store` | `Option<Arc<dyn EventStore>>` |
| `scheduler_signal` | `Option<mpsc::Sender<SchedulerSignal>>` |
| `scheduler_signal_sink` | `Option<Arc<tokio::sync::Mutex<Option<mpsc::Sender<SchedulerSignal>>>>>` |
| `rag_index` | `Option<RagIndexHandle>` |
| `rag_indexer` | `Option<Arc<RagIndexer>>` |
| `live_tokens` | `Option<Arc<AtomicU64>>` |
| `live_input_tokens` | `Option<Arc<AtomicU64>>` |
| `live_output_tokens` | `Option<Arc<AtomicU64>>` |
| `live_cost` | `Option<Arc<Mutex<f64>>>` |

Live counters are initially `None` and populated by `set_live_counters()`. RAG components are lazily initialized on the first call to `run_internal`. `node_overrides` and `event_broadcaster` are set via dedicated setters and are empty/disabled by default.

### Session construction

`Session::new(config, session_id, db_path)` MUST:
1. Load the YAML manifest from `config.graph` via `GraphManifest::load`
2. Convert the manifest to a `GraphSpec` via `to_graph_spec()`
3. Build a `PortRegistry` from the manifest's agents and control nodes
4. Call `validate_graph`; return `EngineError::Graph` if validation fails
5. Resolve the graph directory as the parent of the manifest path
6. Parse `session_id` as a UUID; return `EngineError::Run` if parsing fails
7. Pre-warm the default LLM client for `config.provider.generation_model`

The `db_path` MUST be propagated to all control node subprocesses via `EUREKA_DB_PATH` (see SPEC-0011).

### Node construction

During `run`, the session MUST construct one `BoxedNode` per `GraphNodeSpec`. Construction MUST:
- For agent nodes: build an `LlmAgentNode` from the matching `AgentSpec` and an `LlmClient` for the agent's model (per-agent model override if configured, otherwise the default model); return `EngineError::NodeCreation` if any tool name is `"submit"`
- For control nodes: build a `ControlNode` from the matching `ControlSpec` and the session's `RunEnvironment`
- For test overrides: use the pre-installed `BoxedNode` from `node_overrides`

### Goal injection

`Session::run(goal: serde_json::Value)` MUST inject an `Artifact { kind: "Goal", data: goal }` into every source node identified by `GraphSpec::source_node_ids()`. Each source node receives exactly one `"Goal"` artifact as its initial input. The scheduler MUST start with these pre-injected artifacts.

### Run execution

`run_internal(goal, store, checkpoint)` MUST:
1. If RAG is enabled and not yet initialized, attempt RAG initialization via `build_rag_components`; `live_tokens` and `live_cost` are passed so the RAG indexer increments them per embedding request; failure MUST warn and continue without RAG
2. Create a `RunRecord` with `status: Running`; if `store` is `Some`, save the record
3. Construct all nodes from the spec, using node overrides when present
4. Expand replicas: for each node, resolve the runtime `workers` count via `AgentConfig::resolve_for()` against the runtime TOML config (NOT the YAML manifest). When `workers > 1`, clone the node into N replicas (`{id}.r0`, `{id}.r1`, ...). Expand edges via the cross-product of from-replicas × to-replicas, producing a fully expanded topology.
5. Build an expanded `GraphSpec` from the replica nodes and edges; create a `Scheduler` from it together with the expanded nodes, `Budget`, and `max_in_flight`. If live counters are attached, pass all four (`tokens`, `input_tokens`, `output_tokens`, `cost`) via `Scheduler::with_live_counters()`. Attach the RAG indexer via `with_rag_indexer()` and the checkpoint store via `with_checkpoint_store()` if present. Store the signal sender in `self.scheduler_signal` and propagate to `scheduler_signal_sink` if present.
6. Start an event observer task that forwards events to the broadcaster and persists them to `event_store` if tracing is enabled
7. Inject a `"Goal"` artifact into every source node; run the scheduler with the injected artifacts (or from a `RunCheckpoint` via `run_from_checkpoint` if resuming)
8. After the scheduler completes or errors, drain the event observer task
9. Clear `self.scheduler_signal` to `None` (and the shared sink if present)
10. Update `RunRecord` with the final status and stats; persist if `store` is `Some`
11. Return `RunStats`

### Run statuses

The `RunRecord` status MUST be set as follows:
- Start of run: `Running`
- Scheduler completes without error and budget not exhausted: `Completed`
- Scheduler completes and budget was exhausted: `Cancelled`
- `SchedulerError::Paused`: `Paused`
- `SchedulerError::NodeFailed`: `Failed`
- `SchedulerError::Cancelled`: `Cancelled`
- Any other scheduler error: `Failed`

### Resuming

`Session::resume_with_store(goal, store, checkpoint)` MUST behave identically to `run_with_store` except that it passes the `RunCheckpoint` to the scheduler for identity validation and state restoration.

### Signal propagation

While a run is executing, `Session::scheduler_signal()` MUST return a clone of the active signal sender. It MUST return `None` when no run is executing. The signal sender MUST be cleared immediately after the scheduler run completes or errors.

### Live per-request counters

`Session::set_live_counters(tokens: Arc<AtomicU64>, input: Arc<AtomicU64>, output: Arc<AtomicU64>, cost: Arc<Mutex<f64>>)` MUST store the four shared atomics in the corresponding session fields. During `run_internal`:

1. `tokens` and `cost` are passed to `build_rag_components` so the RAG indexer increments them per embedding request
2. All four counters (`tokens`, `input`, `output`, `cost`) are passed to `Scheduler::with_live_counters()` so they are injected into `NodeCtx` for agent node per-request increments

### Test construction

`Session::from_parts(config, spec, nodes, session_id)` MUST validate the supplied `GraphSpec` against a `PortRegistry` built from the supplied nodes' port declarations. It MUST return `EngineError::NodeCreation` if any node ID in the spec is missing from the `nodes` map.
